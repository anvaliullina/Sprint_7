# Sprint_7 — API-автотесты Яндекс Самокат

Python + `pytest` + `requests` + `allure-pytest`.

**Учебный сервис:** https://qa-scooter.praktikum-services.ru/  
**Документация API:** https://qa-scooter.praktikum-services.ru/docs/

## Что протестировано

- `POST /api/v1/courier` — создание курьера: успех, дубликат, отсутствующие и пустые обязательные поля.
- `POST /api/v1/courier/login` — логин: успех, отсутствующие поля, неверные данные, несуществующий пользователь.
- `POST /api/v1/orders` — создание заказа: BLACK, GREY, оба цвета, пустой массив и отсутствие `color`; параметризация `pytest`.
- `GET /api/v1/orders` — ответ содержит список в `orders`.

В каждой проверке контролируются **HTTP-статус и JSON-тело ответа**. Каждый тест использует новые данные. Курьеры удаляются после теста; заказы по возможности отменяются по `track`.

## Установка и запуск (Windows / PowerShell в VS Code)

Из папки `Sprint_7`:

```powershell
python -m pip install -r requirements.txt
python -m pytest -v --alluredir=allure-results --clean-alluredir
```

После успешного запуска можно открыть локальные результаты командой:

```powershell
allure serve allure-results
```

Для формирования HTML-отчёта в **папке, которую нужно запушить**:

```powershell
allure generate allure-results -o allure-report --clean
```

Важно: в Git добавляется `allure-report/`, а `allure-results/` исключён через `.gitignore`. `allure-report/` появится **после локального прогона**, в ZIP его нет, потому что результаты тестирования нельзя создавать без реального запуска на сервисе.

Если временно недоступен стенд, запросы могут упасть с ошибкой подключения / таймаутом. Это не означает автоматически ошибку в тестовом коде.

## Постман (ручное тестирование)

Импортируй файл `postman/Sprint_7.postman_collection.json` в Postman (`Import`). Затем по очереди выполни «Создать курьера», «Логин курьера», «Создать заказ», «Получить список заказов». Обязательно проверь HTTP-статус и JSON-тело ответа.

Используются переменные коллекции; тестовые логин и пароль для ручных запросов следует обновлять при повторной регистрации. Не отправляй настоящие пароли в публичный репозиторий.

## Сдача проекта

1. Запустить тесты на реальном учебном стенде и убедиться, что проверки пройдены.
2. При необходимости сравнить фактические ответы с документацией и исправить выявленные несоответствия.
3. Сгенерировать `allure-report/` (команда выше).
4. Загрузить код и папку `allure-report/` в новый GitHub-репозиторий Sprint_7. **Не загружать `allure-results/`.**
5. Создать Pull Request из `develop` в `main`, если это требуется инструкцией Практикума.

### Примечание

Этот ZIP содержит **готовый исходный код обязательной части**, однако здесь не было возможности обратиться к учебному серверу и получить действительные HTTP-ответы. Не стоит считать тесты пройденными, пока они не были запущены на твоём компьютере. Дополнительные три ручки из необязательного задания пока не включены, чтобы не усложнять основную сдачу.
